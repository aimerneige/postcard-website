# 片刻 · 明信片生成器

React + Vite + TypeScript 的纯浏览器应用。选择本地图片，制作横向 148 × 105 mm 或竖向 105 × 148 mm 明信片并下载 PNG / 打印 PDF。默认简体中文、M3 风格界面，支持桌面与手机。

## 运行与验证

环境：Node.js 22.12+、npm、Python 3。浏览器测试还需要 Pillow：`python3 -m pip install Pillow`。仓库已包含七款字体。开发和构建命令会校验文件 SHA-256；只有字体缺失或损坏时才从固定的官方来源重新下载。

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

`test:e2e` 会先准备字体、生成测试图片、构建 `dist`，再从本地静态服务器验证 `/` 和 `/postcard/`。测试图片由 `scripts/generate-test-fixtures.py` 生成到被忽略的 `tests/fixtures`。截图、实际下载样本保存在被忽略的 `.local` 中。测试服务器只用于验证，不属于产品。

## 已实现

- 以真实文件签名和浏览器解码判断 JPG、PNG、静态 WebP，拒绝已检测的 APNG / 动态 WebP 以及其他格式。
- 30 MiB 文件上限、40 MP 像素上限；解码前读取尺寸和 EXIF，浏览器按照 EXIF 归一化方向。解码失败保留此前编辑状态。
- 在「图片与构图 → 画布方向」切换横向 / 竖向。切换会重置旋转、缩放和居中位置，保留字体、文字和白条不透明度；换图保留当前画布方向。
- 居中 cover，拖动 / 方向键微调（Shift 加速），100%–400% 相对缩放，90° 顺时针旋转、恢复构图。
- 换图保留字体、文字和白条；旋转保留缩放并居中；恢复只影响构图。
- 横版逻辑画布 1480 × 1050，竖版 1050 × 1480。两种方向均为底部 64px（6.4 mm）白条、16px 边距、32px 字号，默认白色不透明度 30%；竖版仅缩短白条宽度。左右文字框横版各 640px，竖版各 501px，中间至少留 16px，文字过长提示裁切。
- 支持 irohamaru（日语圆体）、Noto 黑体、Noto 宋体、马善政楷书，以及 Lato 英文无衬线、Lora 英文衬线、Caveat 英文手写，共七款字体，左右文字共用选择。切换字体不改变构图、文案或不透明度。
- 字体按需从本站加载，预览、文字溢出测量、PNG 和 PDF 共用字体；加载失败可重试，快速切换不会被过期请求覆盖。
- 字体加载完毕才允许导出；文字过长提示并按固定文字框裁切，不自动缩小或换行。
- 原始像素和有效 PPI 实时显示。实际解码尺寸不一致时显示限制并按实际位图计算，避免高报清晰度。
- 所有最终纸面以白色打底。预览通过 ResizeObserver 与 requestAnimationFrame 合并重绘，不执行全尺寸导出。
- 低于 300 PPI 时使用可取消的确认对话框，允许继续下载。
- 所有内置字体均为 SIL OFL 1.1 开源字体，无需购买使用授权。仓库包含经过校验的字体文件、来源清单和文本许可；构建会把字体复制到 `dist`，详见 [字体授权说明](./FONT_LICENSES.md)。

## 导出规格与排版

| 项目 | 规格 |
| --- | --- |
| PNG | 横版 1748 × 1240 px / 竖版 1240 × 1748 px，RGB / 不透明白底，pHYs 11811 像素/米（约 300 PPI） |
| PDF | 单页，横版 148 × 105 mm / 竖版 105 × 148 mm，嵌入与 PNG 相同的栅格画面；字体已栅格化，无远端字体依赖 |
| 文字基线 | 字母基线固定在白条中心下 11 个逻辑像素 |
| PPI | `254 / coverScale / zoom`，coverScale 使用旋转后的实际渲染源尺寸 |

打印 PDF 选择「实际大小 / 100%」，不要选择「适合页面」。整数像素取整意味着 PNG 的物理尺寸有极小舍入误差；PDF 页面尺寸精确。300 PPI 导出不会补充原图中不存在的细节。

原始 CSS 未明确行高，不能保证与原网页逐像素一致；新 Canvas 基线是明确的实现决定。Canvas 不提供通用的 OpenType `locl` 开关，不能宣称原右侧 CSS 的所有字体特性完全复刻。左右文案默认留空，默认字体是针对日语字形优化的 irohamaru Regular，文件来自作者官方归档并与最初附件的 SHA-256 一致；选择其他字体时，缺失字符优先回退到内置 irohamaru，再回退到浏览器无衬线字体。中文字库不保证覆盖所有生僻字。

附件原工程的底图与文字条是独立页面。本实现根据需求将两者组合到底部；初始页面保持空画布。原始 JPEG 只用于本地检查，不进入 `src`、`public` 或 `dist`。

## 本地与隐私边界

图片、文字、裁切及导出仅保存在浏览器内存；刷新后清空。没有后端、图片上传、统计、第三方字体服务、远程图片 URL、localStorage、Service Worker 或云存储。站点加载时只获取自身静态资源；PDF 模块在首次导出 PDF 时从同一站点加载。

解码结果只保留一份当前有效 ImageBitmap，换图和卸载时释放旧位图；异步序号阻止旧请求覆盖新结果。下载 Blob URL 在 30 秒后释放。首版依赖支持 createImageBitmap、FontFace、Canvas 和 dialog 的现代浏览器。自动化验证使用 Chromium；iOS Safari / Firefox 真机和实际打印未验证。

## 仓库与构建产物

Git 仓库保存源码、测试逻辑、来源校验值、文本许可及七款字体文件。字体是唯一提交的二进制资源；测试图片、`dist`、发布 ZIP 和 `node_modules` 仍在本地生成并忽略。执行 `npm run assets` 会校验字体，缺失时从固定来源恢复；构建产物可用 `npm run build` 重新生成。

## 手动发布

详见 [DEPLOYMENT.md](./DEPLOYMENT.md)。直接使用 `dist` **里面的内容**，包括隐藏文件 `.nojekyll`，不是把外层 `dist` 目录放到发布仓库根目录。

本项目没有 `.github/workflows`，未创建仓库、推送、部署或修改 DNS。
